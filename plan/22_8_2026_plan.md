# Refactor Dynamic Form Architecture

This plan aims to refactor the dynamic form core logic and renderer to eliminate `ngSwitch` and implement a scalable, type-safe Builder hierarchy combined with Dynamic Component Loading in Angular.

## User Review Required

> [!IMPORTANT]  
> This refactoring will affect the core schema models, builders, and the main rendering component. Existing logic using `new FieldBuilder()` will be adapted to use a new `FieldBuilderFactory`.

## Proposed Changes

### Core Models & Builders

We will refactor the models and the `FieldBuilder` to follow a cleaner OOP structure with inheritance.

#### [MODIFY] [schema.model.ts](file:///d:/PRACTICE/ANGULAR/dynamic-form/src/app/core/models/schema.model.ts)

- Convert `FieldSchema` into a base interface `BaseFieldSchema`.
- Create specific interfaces: `TextFieldSchema`, `SelectFieldSchema`, `CheckboxFieldSchema`, etc.
- Export `FieldSchema` as a union type of all specific interfaces to maintain type safety across the app.

#### [MODIFY] [field.builder.ts](file:///d:/PRACTICE/ANGULAR/dynamic-form/src/app/core/builders/field.builder.ts)

- Create an abstract `BaseFieldBuilder<T extends BaseFieldSchema>`.
- Create specific builders: `TextFieldBuilder`, `SelectFieldBuilder`, etc., that extend `BaseFieldBuilder`.
- Create a `FieldBuilderFactory` with a `create(type: FieldType)` method to return the appropriate builder instance.

#### [MODIFY] [field.builder.spec.ts](file:///d:/PRACTICE/ANGULAR/dynamic-form/src/app/core/builders/field.builder.spec.ts)

- Update unit tests to use `FieldBuilderFactory.create(type)` instead of `new FieldBuilder(type)`.

---

### Shared Components (Dynamic Form Renderer)

We will remove `ngSwitch` from the template and replace it with Angular's `ngComponentOutlet`.

#### [NEW] `dynamic-form-renderer/components/*`

- Create a folder `src/app/shared/components/dynamic-form-renderer/components/`.
- Generate standalone field components:
  - `TextFieldComponent`
  - `TextareaFieldComponent`
  - `NumberFieldComponent`
  - `SelectFieldComponent`
  - `RadioFieldComponent`
  - `CheckboxFieldComponent`
  - `DateFieldComponent`
- Each component will have `@Input() field!: any` and `@Input() formGroup!: FormGroup`.

#### [MODIFY] [dynamic-form-renderer.component.html](file:///d:/PRACTICE/ANGULAR/dynamic-form/src/app/shared/components/dynamic-form-renderer/dynamic-form-renderer.component.html)

- Remove the `<ng-container [ngSwitch]="field.type">` and all its cases.
- Use `<ng-container *ngComponentOutlet="getComponentForType(field.type); inputs: { field: field, formGroup: formGroup }"></ng-container>` inside the `*ngFor` loop.

#### [MODIFY] [dynamic-form-renderer.component.ts](file:///d:/PRACTICE/ANGULAR/dynamic-form/src/app/shared/components/dynamic-form-renderer/dynamic-form-renderer.component.ts)

- Create a `fieldComponentRegistry` mapping `FieldType` to the newly created standalone components.
- Add the `getComponentForType` method.
- Clean up unused Ng-Zorro imports (they will be moved to their respective specific field components).
